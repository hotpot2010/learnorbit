# 笔记缓存功能实现说明

## 概述

实现了笔记内容的智能缓存功能，避免重复调用LLM生成相同的笔记，提升响应速度并节省API成本。

**注意**: 只缓存LLM生成的笔记内容，**不缓存视频截图**（因为截图是实时捕获的）。

## 缓存策略

### 缓存键 (Cache Key)

```
MD5(video_url :: knowledge_point_name)
```

**组成部分**:
- `video_url`: 视频的完整URL（如Bilibili视频链接）
- `knowledge_point_name`: 知识点名称（如"访问Python官网下载"）

**示例**:
```
视频: https://www.bilibili.com/video/BV1Jgf6YvE8e?p=3
知识点: "访问Python官网下载"
缓存键: MD5("https://www.bilibili.com/video/BV1Jgf6YvE8e?p=3::访问Python官网下载")
       = "a1b2c3d4e5f6..."
```

### 缓存有效期

- **默认**: 7天（168小时）
- **可配置**: 通过 `max_age_hours` 参数调整

### 缓存目录

```
backend/cache/notes/
├── note_a1b2c3d4e5f6....json  # 知识点1的笔记
├── note_x9y8z7w6v5u4....json  # 知识点2的笔记
└── ...
```

## 架构设计

### 1. 后端服务

#### `NoteCacheService` (笔记缓存服务)

**文件**: `backend/app/services/note_cache_service.py`

**核心方法**:

```python
class NoteCacheService:
    def get_cached_note(
        self, 
        video_url: str, 
        knowledge_point_name: str,
        max_age_hours: Optional[int] = None
    ) -> Optional[str]:
        """获取缓存的笔记"""
        
    def set_cached_note(
        self,
        video_url: str,
        knowledge_point_name: str,
        note: str,
        metadata: Optional[Dict[str, Any]] = None
    ):
        """缓存笔记"""
        
    def clear_cache(self, video_url: Optional[str] = None):
        """清除缓存"""
        
    def get_cache_stats(self) -> Dict[str, Any]:
        """获取缓存统计信息"""
```

#### 笔记API路由更新

**文件**: `backend/app/api/routes/notes.py`

**新增字段**:

```python
class NoteGenerationRequest(BaseModel):
    knowledge_point_name: str
    transcript_segment: str
    video_title: Optional[str] = None
    video_url: Optional[str] = None  # ✅ 新增：用于缓存

class NoteGenerationResponse(BaseModel):
    success: bool
    note: Optional[str] = None
    error: Optional[str] = None
    from_cache: bool = False  # ✅ 新增：标识是否来自缓存
```

**处理流程**:

```python
@router.post("/generate")
async def generate_note(request: NoteGenerationRequest):
    # 1. 尝试从缓存获取
    if request.video_url:
        cached_note = note_cache_service.get_cached_note(
            video_url=request.video_url,
            knowledge_point_name=request.knowledge_point_name,
            max_age_hours=24 * 7  # 7天
        )
        
        if cached_note:
            return NoteGenerationResponse(
                success=True,
                note=cached_note,
                from_cache=True  # ✅ 标记为缓存
            )
    
    # 2. 缓存未命中，调用LLM生成
    note_content = await doubao_service.generate_outline(...)
    
    # 3. 缓存新生成的笔记
    if request.video_url:
        note_cache_service.set_cached_note(
            video_url=request.video_url,
            knowledge_point_name=request.knowledge_point_name,
            note=note_content
        )
    
    return NoteGenerationResponse(
        success=True,
        note=note_content,
        from_cache=False  # ✅ 标记为新生成
    )
```

## 性能提升

### 时间对比

| 操作 | 无缓存 | 有缓存 | 提升 |
|------|--------|--------|------|
| 首次生成 | ~3-5秒 | ~3-5秒 | - |
| 再次访问 | ~3-5秒 | <100ms | **30-50x** |

### 成本节省

- **LLM API调用**: 缓存命中时不调用，节省100%的API费用
- **带宽**: 减少重复的API请求和响应
- **用户体验**: 即时响应，无需等待

## 使用场景

### 场景1: 同一视频多次学习

用户在学习同一个视频时，为不同知识点生成笔记：

1. **第一次**: 为"知识点A"生成笔记 → 调用LLM → 缓存结果
2. **第二次**: 为"知识点B"生成笔记 → 调用LLM → 缓存结果
3. **第三次**: 再次查看"知识点A"的笔记 → **从缓存加载** ✅

### 场景2: 多用户学习同一视频

多个用户学习同一个Bilibili视频：

1. **用户A**: 为"Python安装"生成笔记 → 调用LLM → 缓存
2. **用户B**: 为"Python安装"生成笔记 → **从缓存加载** ✅
3. **用户C**: 为"Python安装"生成笔记 → **从缓存加载** ✅

### 场景3: 刷新页面后恢复笔记

用户刷新页面或重新打开视频：

1. **之前**: 已为多个知识点生成笔记
2. **刷新页面**: 知识点卡片重新加载
3. **点击笔记按钮**: **从缓存加载**，无需等待 ✅

## 缓存策略优化

### 1. 缓存失效

**自动失效**:
- 默认7天后自动过期
- 可通过 `max_age_hours` 参数自定义

**手动失效**:
```python
# 清除特定视频的缓存
cache_service.clear_cache(video_url="...")

# 清除所有缓存
cache_service.clear_cache()
```

### 2. 缓存预热

对于热门视频，可以预先生成并缓存笔记：

```python
# 批量生成热门视频的笔记
popular_videos = [
    ("https://bilibili.com/video/BV123", "知识点1"),
    ("https://bilibili.com/video/BV123", "知识点2"),
    # ...
]

for video_url, knowledge_point in popular_videos:
    # 生成笔记（会自动缓存）
    await generate_note(...)
```

### 3. 缓存容量管理

定期清理旧缓存：

```bash
# 创建定时任务清理7天以上的缓存
# crontab -e
0 3 * * * python backend/cleanup_old_cache.py
```

## 与截图的区别

| 特性 | 笔记内容 | 视频截图 |
|------|----------|----------|
| 是否缓存 | ✅ 是 | ❌ 否 |
| 原因 | LLM生成成本高，内容不变 | 实时捕获，每次可能不同 |
| 存储位置 | 后端文件系统 | 前端Base64（临时） |
| 有效期 | 7天 | 页面会话期间 |
| 大小 | ~100-500 bytes | ~50-200 KB |

## 故障排查

### 问题1: 缓存始终未命中

**检查**:
- 确认 `video_url` 参数是否传递
- 确认每次传递的 `video_url` 和 `knowledge_point_name` 完全一致
- 查看后端日志中的缓存键

### 问题2: 缓存目录权限错误

**解决**:
```bash
# 确保缓存目录可写
chmod 755 backend/cache/notes/
```

### 问题3: 缓存文件损坏

**解决**:
```python
# 清除所有缓存，重新生成
cache_service.clear_cache()
```
